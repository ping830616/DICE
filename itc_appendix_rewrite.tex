This appendix extends the methodological context of the paper. It records the released dataset, the tiered telemetry that defines the mixed and full profiles, the fixed \textsc{DICE} configuration used throughout the study, the Apple Silicon host on which the data were collected, the crash-aware collection protocol, and the grounded LLM-based triage method.~\footnote{All scripts supporting this work, together with the released processed dataset and supporting artifacts, are available at \url{https://github.com/ping830616/DICE}.} It is not intended to repeat the results already reported in the main text. \subsection{Crash-Aware Collection Protocol}\label{app:crash_protocol}

Section~\ref{subsec:results_crash} reports the crash-aware warning behavior. This appendix records how that extension was collected. The crash-aware extension is not a separate benchmark with a different detection rule. It is a matched recollection protocol built around four workload-stressor families: \texttt{BROWSER/BRANCH}, \texttt{PY\_AI/CACHE}, \texttt{PY\_STATS/ATOMIC}, and \texttt{VIDEO\_SW/MEMBW}. Each pilot contains one \texttt{NOMINAL} run, one \texttt{*\_CONTROL} anomaly run that exits cleanly, and one \texttt{*\_ABORT} anomaly run that ends with a real user-space crash through the DICE wrapper. When Tier-0, Tier-1, and Tier-2 are all collected, this design yields 12 cases and 36 capture runs.

The tracked repository view is intentionally lightweight. The full local pilot bundle is much larger and may include copied crash reports, filtered \texttt{log show} windows, screenshots, per-case tier outputs, and downstream analysis folders. The repository therefore tracks the pilot manifest and the derived summaries used by the notebook, while leaving the large machine-generated crash payload in the local collection tree when that payload is materialized. This design keeps the public repository reviewable without changing the crash-aware methodology itself.

\subsection{Grounded LLM-Based Triage Workflow}\label{app:llm_method}

Section~\ref{subsec:results_llm} explains the role of the LLM-based triage layer. This appendix records the method. The workflow begins after \textsc{DICE} has already produced its anomaly evidence, diagnosis summary, and warning context. It reads \texttt{case\_diagnosis\_summary.csv}, exports one structured case card per anomalous Tier-0/1/2 case, converts that card into grounded evidence text, builds a prompt bundle, runs a local language model, and scores the generated summary against the source case card. The language model does not receive raw traces, hidden logs, or any external telemetry source.

The shared system prompt makes that restriction explicit. It tells the model that it may use only the structured \textsc{DICE} evidence supplied to it and that any conclusion should remain tentative when the evidence is incomplete. The scored local baseline uses \texttt{mlx-community/Qwen2.5-0.5B-Instruct-4bit} through \texttt{mlx\_lm}. The released local path uses deterministic decoding with a fixed seed of 7, greedy sampling, and a maximum generation length of 160 tokens. A broader model catalog is also tracked for offline comparison, but the portable scored baseline remains the small MLX-backed Qwen model because it can be rerun directly on Apple Silicon.

The grounding checks are also fixed. The scoring records \textit{grounded\_core}, \textit{cue\_coverage}, and \textit{hallucination\_flag}. In practice, these checks ask whether the generated summary preserves the dominant tier, preserves the dominant mechanism, mentions leading cues such as the top feature and top mechanism, and avoids unsupported claims about tiers or mechanisms. This is why the LLM layer should be read as a grounded interpretation module rather than as part of the detector itself.
